# Security & Confidentiality Policy

This public portfolio follows a publication-safety standard.

## Professional affiliation

An employer or professional affiliation may be named when that relationship is authorized for public disclosure. **Naming an affiliation does not authorize publication of private work.**

References to **FoundLab** identify authorized professional context only. This portfolio distinguishes synthetic laboratories, public GitHub governance evidence and anonymized summaries of real assessments. None should be interpreted as evidence of the current private infrastructure or security posture of any employer.

## Never publish

Do not publish private project or client names; production identifiers; real service-account identities; credentials, tokens, keys or secrets; private endpoints or raw operational logs; internal ticket/workflow identifiers; proprietary source code; reconstructable private architecture; non-public vulnerabilities or unresolved findings.

## Safe transformation rule

Classify each release before publication:
- **Synthetic laboratory** — fictional evidence, code or architecture used for reproducible exercises.
- **Anonymized real work** — actual investigation or assessment activity, with primary evidence withheld and all identifiable/reconstructable non-public details removed.
- **Public repository validation** — outcomes independently visible in this personal public GitHub repository (PRs, checks and branch rules).

A case summary must not imply that private findings are publicly reproducible or that the employer's deployed configuration was verified. Sanitization must not fabricate professional experience, tests, findings, fixes, independent review or signatures. Portfolio examples may omit material necessary to reproduce real outcomes.

**Licensing note:** the repository's MIT license does not establish rights to reproduce third-party confidential source code or private employer records. Publication rights must be confirmed before any release.

## Pre-publication gate

Before publication, verify:

- scope and authorization;
- employer/client disclosure rights;
- removal of reconstructable identifiers;
- separation between professional affiliation and public artifact attribution;
- claims match available evidence;
- limitations are explicit;
- synthetic material is clearly identified;
- no secret, private project detail or non-public finding is present.

When in doubt, do not publish the sensitive detail.

## Active competitions and third-party training content

Public portfolio notes may summarize participation and generic methodology in a simulated CTF, but **challenge solutions, flags, answer-bearing indicators, raw telemetry, event-specific query strings and private forensic write-ups are withheld** while disclosure rights are unverified. Event closure alone is **not** authorization to disclose.

A public participation summary should clearly distinguish challenge completion from ranking, prize eligibility, certification and organizer endorsement. Any assistance (including conversational AI) should be disclosed honestly. A manual review of the event's rules and any organizer permissions is required before a solution-level publication.
